- 사용 스킬: design-taste-frontend v2.

- 실제 조작: 문장으로 의류 디자인을 생성·수정하고, 그 결과를 선택한 성북 업체의 PDF 또는 이메일 제작자료로 연결한다.
- 기존 소재: 반팔·후드·과잠, 동아리 문구, 캠퍼스 배지, 크루 웨이브, 업로드한 로고, 성북 지역, 업체별 최소 수량, 인쇄 규격, PDF·이메일 양식, 브라우저 저장 디자인.
- 사용자의 뉴모피즘 요청에 따라 회청색 배경, 부드러운 양방향 그림자, 눌린 입력창과 선택 상태, 파란 주 동작 버튼을 사용했다. 스킬의 그림자 금지보다 사용자 지시를 우선했다.
- 마케팅 랜딩 구성, 장식 사진 최소 수량, 과도한 등장 모션은 단일 작업 흐름과 단순화 요청에 맞지 않아 적용하지 않았다. 외부 이미지·영상·새 가상 고객 데이터는 추가하지 않았다. 의류는 기존 React Konva 렌더링이다.

## 최종 흐름

1. `/`는 `/design`으로 연결한다. 디자인 화면은 대화 입력과 미리보기 두 영역이다. 저장은 디자인 한 종류로 통일했다.
2. 업체 카드와 기존 필터를 유지한다. 생성 결과가 있어야 업체 선택을 진행한다.
3. 필요한 주문정보를 입력하고 업체별 도안을 확인한다. 인쇄 크기·추가 요청은 접어두며, 도안 확인 화면은 실제 도안을 먼저 보여준다. 자세한 주문정보와 다운로드는 펼쳐서 확인한다.
4. 체험 전달 완료 후 견적 대기 화면으로 이동한다. 마이페이지의 대기 탭으로 이어진다.

상단은 반티 만들기와 마이페이지만 남긴다. 마이페이지는 저장한 디자인과 견적 대기 두 항목이다. 이전 IndexedDB 자료를 삭제하지 않으며, 현재 목록에는 저장한 디자인만 표시한다. 견적에는 제출 당시 디자인과 주문정보가 보존된다. 저장 디자인을 불러오면 이전 업체 선택과 주문정보를 초기화해 다른 작업의 조건이 섞이지 않게 했다.

## 연동 범위

기존 디자인 생성 API와 견적 API는 mock이다. 실제 생성형 AI 호출이나 업체 발송은 이번 UI 변경 범위에서 새로 연결하지 않았다. 모든 업체는 기존 가상 데이터이며, 대기 화면과 마이페이지에 실제 전송·회신이 없다는 사실을 표시한다. 실서비스 전환 시 실제 업체, AI 생성, 전송 및 회신 연동이 필요하다.
