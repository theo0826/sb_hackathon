# 재사용 의류 모델과 도안 레이어 설계안

상태: 3D 의류 자산 고도화는 제안 단계. 고객 UV와 업체 봉제 패턴을 별도 자료로 관리하고 AI가 업체 목업 3종으로 변환하는 프로세스는 [UV·패턴 변환 문서](UV-PATTERN-CONVERSION.md)에 따라 구현했다. 의류 GLB 교체·Higgsfield 생성·유료 API 실행은 하지 않았다. 사용자 요청으로 `OPENAI_ENABLED=false`를 유지한다.

## 현재 코드에서 확인한 것

- `lib/garment-model.ts`가 몸통 표면을 수식으로 만들고 원통형 소매, 후드, 단추 등을 붙인다. AI가 3D 구조를 생성하는 방식은 아니다.
- 인쇄 도안은 별도의 곡면 메시에 얹는다. 실제 옷의 패널별 UV 전개도에 합성하지 않는다.
- `GarmentPreview3D.tsx`는 디자인 값이 바뀔 때마다 의류와 재질을 폐기하고 다시 만든다. 이 작업은 브라우저 연산이며 API 토큰을 소모하지 않지만 구조 재사용과 화면 안정성은 개선할 수 있다.
- 색상·위치 같은 대화 지시도 현재는 텍스트 모델을 거쳐 해석한다. 이미지 재생성은 피할 수 있어도 텍스트 호출은 남는다.
- 견적 AI는 이메일 제목·본문을 생성하지만 서버가 그 값을 검증한 주문 정보로 다시 작성한다. 불필요한 출력 항목을 없앨 수 있다.

## 제안하는 기본 구조

한 번 준비하는 자산:

- 의류 종류와 핏별 검수된 GLB: 우선 반팔 1종, 다음 후드와 과잠.
- 부드러운 몸통·연결된 어깨·열린 목과 소매·원단 두께·봉제선·자연스러운 정지 주름.
- 앞판·뒷판·소매·후드의 겹치지 않는 UV 영역. 뒷판 문구가 뒤집히지 않는 방향.
- 기본 원단의 normal/roughness, 모델의 실제 단위·방향, 인쇄 가능한 영역과 치수.
- 조명·카메라·미리보기 설정과 모바일용 가벼운 자산.

사용자가 만드는 데이터:

- 선택한 기본 의류 ID와 원단 색상.
- 이미지·벡터·문구를 별도 레이어로 저장한 인쇄 도안.
- 레이어별 앞/뒤/소매 위치, 실제 인쇄 가로·세로(cm), 회전, 배율.
- 제작 방식·수량·업체·납기 등 주문 정보.

렌더링 순서: 기본 모델 로드 → 원단 재질 적용 → 해당 패널의 2D 도안 합성 → UV 텍스처 적용 → 브라우저에서 실시간 회전·확대. 모델과 조명은 고정하고 바뀐 재질·텍스처만 갱신한다. `CanvasTexture` 또는 검수된 인쇄용 UV 채널을 사용하며, 원단의 반복 UV와 도안의 패널 UV를 분리한다.

사용자가 말한 전개도는 이 단계의 UV 맵과 유사하다. 다만 UV 맵은 화면의 표면 대응표이며 봉제용 실물 패턴을 보장하지 않는다. 공장에는 원본 도안·cm 규격·패널/면별 배치도·미리보기를 별도로 전달한다. 3D 스크린샷이나 UV 아틀라스를 인쇄 원본으로 취급하지 않는다.

## Higgsfield의 역할

읽기 전용 모델 카탈로그와 `/3d-jutsu` 작업 지침을 확인했다.

- 3D Jutsu는 Blender 씬을 편집하고 GLB와 Blender 원본을 내보내는 기능을 제공한다. 기본 의류 자산 제작·검수 단계에서 사용할 수 있다.
- 이미지→3D 카탈로그에는 Meshy와 SAM 계열이 있다. 생성된 모델이 의류용 열린 내부, 정확한 소매/목, 제작에 맞는 UV를 갖추었다고 보장할 수 없으므로 최종 모델로 바로 사용하지 않는다.
- 현재 3D Jutsu의 자산 가져오기는 연결 도구의 curated catalog GLB만 지원한다. 임의의 사용자 GLB나 이미지→3D 결과를 다시 넣을 수 있다고 가정하지 않는다. 직접 만든 씬을 내보내거나, 별도 Blender 환경에서 외부 파일을 검수하는 경로를 구분한다.
- 절차적 재질과 씬 조명은 GLB에서 동일하게 전달되지 않을 수 있다. 자산은 표준 재질·베이크한 맵으로 전달하고 사이트의 실제 Three.js 렌더러에서 검수한다.
- Higgsfield는 매 사용자 요청마다 호출하는 서비스가 아니라 기본 자산을 준비하는 도구로 배치한다. 생성 모델과 렌더 기반 AI 이미지/영상은 별도 크레딧을 쓸 수 있다. 이번에는 생성·씬 편집을 실행하지 않았고 무료라고 가정하지 않는다.

## 비용을 줄이는 처리 규칙

| 요청 | 처리 | 런타임 AI 호출 목표 |
| --- | --- | --- |
| 옷 회전·확대·앞뒤 보기 | 브라우저 카메라 | 0 |
| 의류 색상 변경 | 재질 색상 | 0 |
| 도안 이동·크기·회전 | 레이어 좌표 및 합성 | 0 |
| 문구·글꼴 변경 | SVG/Canvas 문구 레이어 | 0 |
| 준비된 배지·타이포·패턴 선택 | 저장된 벡터/이미지 조합 | 0 |
| 단색 로고의 색상 변경 | 분리된 색상 마스크 | 0 |
| 명확한 단순 대화 지시 | 제한된 로컬 명령 해석 | 0 |
| 복잡한 디자인 지시 | 짧은 구조화 텍스트 응답 | 필요할 때 1 |
| 새로운 일러스트·로고 요청 | 해당 도안만 이미지 생성 | 필요할 때 이미지 1, 해석 호출 선택 |
| 같은 결과 다시 열기 | 저장된 자산·결과 조회 | 0 |
| 업체 도안·봉제 패턴 변환 | 고객 UV + 업체 목업 양식 → AI 변환·역검증 | 새 업체/UV 변환 시 필요 |
| 변환된 도면의 PDF/이메일 작성 | 검증한 AI 명세의 렌더링 | 0 |
| 자유형 제작 설명 필요 | 짧은 설명 생성 후 재사용 | 선택적 1 |

로컬 명령 해석은 의미가 확실한 표현에만 적용한다. 모호한 지시는 임의로 수정하지 않고 UI에서 확인하거나 유료 AI 사용을 사용자가 선택하게 한다. 색상·위치 편집을 하다가 이미지 생성 비용이 자동 발생하지 않도록 편집과 새 도안 생성을 분리한다.

그림 속 문구를 AI가 이미지에 그려 넣으면 오탈자 수정에도 이미지 편집이 필요하다. 가능하면 그림과 문구를 분리하고, 배지·타이포는 SVG 템플릿을 사용한다. 완성 도안은 원본 레이어와 합성 결과를 함께 보관한다.

텍스트 모델에는 최근 지시와 필요한 디자인 상태만 전달한다. 고정 지침은 반복 접두사로 유지해 공급자의 prompt caching 조건에 맞출 수 있지만 짧은 요청에 캐시 혜택이 있다고 가정하지 않는다. 절감률은 실제 호출 수·사용량을 측정하기 전에는 표시하지 않는다.

현재 requestKey는 동일 요청의 중복 결제를 막지만 같은 내용을 새 requestKey로 보내면 새 작업이다. 내용 캐시는 별도로 설계한다. 소유자, 원본 도안 해시, 지시, 생성 옵션, 모델 및 템플릿 버전을 키로 삼고 동일 결과 재사용과 새 변형 요청을 구분한다. 다른 사용자의 비공개 도안은 캐시로 공유하지 않는다.

사용자 확정 방향에 따라 고객 UV와 업체 봉제 패턴은 별도 자료이며 AI가 업체 형식으로 변환한다. 변환 좌표·패널·설명은 결과에 함께 저장하고 반복 조회·문서 렌더링에 재사용한다. 업체별 필수 항목·최소 수량·지원 방식·인쇄 영역과 역변환 일치 여부는 코드로 판정한다. 가격·납기는 업체가 확정하며 AI가 지어내지 않는다.

## 구현 순서와 완료 기준

1. **반팔 자산 1종부터:** 모델, UV 패널, 재질, 정면·측면·뒷면 품질을 검수한다. 실제 GLB 후보를 확인하기 전에는 최종 폴리곤/파일 크기를 확정하지 않는다.
2. **현재 뷰어 교체:** 기본 모델을 캐시하고 좌표/재질 업데이트만 수행한다. WebGL 미지원 시 현재 2D 미리보기를 유지한다.
3. **문구와 도안 레이어 분리:** 앞·뒷면을 독립 저장하고 사용자가 직접 편집한다. 기존 `Design` 자료는 호환 어댑터로 읽는다.
4. **무료 편집 경로:** 색상·크기·위치·문구·준비된 템플릿은 API 없이 처리한다. 모호한 대화 지시의 처리 방식을 분명히 한다.
5. **견적 템플릿과 내용 캐시:** 업체 양식은 코드로 작성하고 AI 설명만 선택적으로 생성한다. 필요 없는 AI 출력 필드를 삭제한다.

완료 기준: 앞·뒤·소매 UV가 겹치지 않음, 문구 뒤집힘·도안 늘어남·봉제 경계 끊김 검수, 예시 cm 규격과 실제 제작 규격 구분, 작은 편집에서 모델 재생성이나 네트워크 AI 호출 없음, 모바일 메모리/프레임/텍스처 해제 확인, 원본 인쇄 도안과 3D 프리뷰 분리, 저장 후 동일 배치 복원, 실제 브라우저의 내보내기 이미지/PDF 검수.

## 확인한 공식 자료

- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html): GLB/glTF 자산 로드 및 압축 확장 지원.
- [Three.js Texture](https://threejs.org/docs/pages/Texture.html): UV 채널, 변환, 색 공간, 텍스처 갱신.
- [Three.js CanvasTexture](https://threejs.org/docs/pages/CanvasTexture.html): 브라우저 합성 캔버스의 텍스처 적용.
- [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching): 반복 접두사의 캐시 조건. 캐싱은 AI 호출 자체를 없애지 않는다.

Higgsfield 기능 범위는 이번 세션의 읽기 전용 모델 카탈로그와 3D Jutsu 작업 지침을 근거로 했다. 생성 품질과 실제 제작비는 아직 검증하지 않았다.
