# 모바일 엄격 검수 결과

검수일: 2026-10-30. 기존 디자인 방향과 사용자가 제공한 Figma를 유지했다. Chrome 실제 렌더링과 CDP 터치 이벤트를 사용했다. 물리 기기나 iOS Safari에서 실행한 검수는 아니다.

## 수정한 문제

| 항목 | 발견한 문제 | 조치 |
| --- | --- | --- |
| 메인 첫 진입 | 모바일 헤더 60px과 작업 영역의 높이 계산 56px이 달라 불필요한 세로 스크롤 발생 | 작업 영역을 실제 헤더 높이에 맞춤 |
| 메인 예시/입력창 | 예시 마지막 카드와 입력창 사이가 약 8px로 붙음 | 첫 진입의 장면 하단 여백을 보정; 390px에서 최소 20px 간격 검증 |
| 모바일 저장 버튼 | PC용 `저장하기`와 아이콘이 작은 버튼 안에 표시 | Figma처럼 `저장` 13px로 표시, 저장 기능 유지 |
| 견적 시트 | 설명·의류 행이 중복되고 요약 금액이 작은 텍스트로 흩어짐 | `예상 견적` 제목, 핸들, 의류 미리보기, 수량, 배경이 있는 금액 요약과 큰 주문 버튼으로 정리 |
| 견적 시트의 선 | 이전 테마의 선이 수량 아래에도 표시됨 | Figma의 구분 위치를 유지하고 불필요한 하단 선 제거 |
| 낮은 화면의 견적 시트 | 화면 높이보다 큰 시트에 높이 제한/내부 스크롤이 없음 | 최대 높이 `100dvh - 16px`, 내부 스크롤과 overscroll 제한 적용 |
| 좁은 화면의 금액 | 320px에서 총액의 단위가 다음 줄로 떨어짐 | 총액을 별도 행에 배치해 숫자와 원 단위를 함께 유지 |
| 820px 주문서 | 입력 필드가 14px로 내려감 | 입력 필드를 16px로 유지 |

## 확인 범위와 결과

- 화면 크기: 320×568, 360×740, 390×844, 430×932, 768×1024, 820×900. 추가로 390×500 메인, 390×440 입력/견적 시트 확인.
- 85개 화면·메뉴 상태: 온보딩, 메인 첫 진입, 주문서, 견적 수신, 요청서, 마이페이지 디자인/주문/이용 방법과 각 메뉴.
- 측정 결과: 문서 가로 넘침 0건, 깨진 이미지 0건, 16px 미만 텍스트 입력 필드 0건, 실행 오류 0건.
- 생성 상태: 검증용 AI 응답과 실제 WebGPU 렌더러로 로딩/생성 결과, 견적 시트, 앞판/뒤판/소매/전체 편집 화면을 확인. 320/390/430/820px 생성 결과에서 가로 넘침 없음.
- 실제 터치 이벤트: 예시 문장 선택 후 입력창 포커스, 공통 메뉴 열기와 이용 방법 이동, 수령일/주소 필드 선택, 요청서 확인 체크, 로고 뒤판 배치 통과.
- 낮은 화면: 주소 필드를 화면 중앙으로 스크롤한 뒤 다른 요소에 가리지 않음. 견적 시트는 화면 안에 제한되고 내부 스크롤 후 주문 버튼의 실제 히트 테스트 통과.
- 긴 입력값: 긴 단체명과 이메일을 넣어도 제작 요청서 가로 넘침 없음.
- 작은 라디오/체크박스는 Figma 원형 크기를 유지하되 실제 클릭 가능한 라벨 행/영역으로 검증했다.
- TypeScript, 변경 컴포넌트 ESLint, 프로덕션 빌드, 기존 9개 단위 테스트 묶음 통과. 소스 taste lint 실패 0건. 기존 미입력 가격의 대시 표기에 대한 경고는 의미 있는 UI 표기로 유지했다.

소프트 키보드는 실제 OS 키보드를 열지 않고 가용 화면 높이를 줄여 확인했다. Safari의 날짜 선택기·주소창 변화·실제 기기의 safe-area 동작은 이 결과로 검증했다고 간주하지 않는다.

## 재현 자료

- `.tools/mobile-strict-audit.mjs`, `.tools/mobile-strict-report.json`: 85개 상태 측정.
- `.tools/mobile-strict-interactions.mjs`: 터치·포커스·긴 입력값 검증.
- `.tools/mobile-strict-generated.mjs`: 실제 3D, 견적 시트, 낮은 화면, 로고 터치 배치 검증.
- `.tools/mobile-strict-*.png`, `.tools/figma-strict-*.png`: 실제 브라우저 캡처. 전체 페이지 캡처의 중간에 고정 CTA가 보이는 것은 촬영 시 뷰포트의 하단 위치이며, 해당 위치에 문서 내용이 영구적으로 덮인다는 의미는 아니다. 별도의 스크롤/히트 테스트로 접근 가능 여부를 확인했다.
