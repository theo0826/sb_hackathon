# ClothSim 프론트 시연

작업 브랜치: `codex/clothdata-demo-integration`. 시작 기준은 main의 `7fb86fc`입니다.
이 브랜치를 push하면 검사와 정적 미리보기 artifact만 생성합니다. 운영 GitHub Pages 배포는 기존 main 워크플로에서 관리합니다.

## 실행

Node.js 24에서 `npm ci` 후 `npm run dev`를 실행합니다. 이 컴퓨터에서는 `run-dev.cmd`로 실행할 수 있습니다.
주소는 `http://127.0.0.1:3000/design/`입니다. 최신 Chrome 또는 Edge의 그래픽 가속을 켜고 사용하세요.

ClothSim은 팀원의 Worker(`https://clothsim-api.set35230.workers.dev`)를 사용합니다. 개발 PC에서도 별도 Ollama 설치 없이 동일한 서버를 호출합니다.
`NEXT_PUBLIC_CLOTH_WORKER_URL`로 주소를 변경할 수 있으며 API 비밀 키는 프론트에 넣지 않습니다.
기존 `NEXT_PUBLIC_AI_DESIGN_URL`은 인쇄 이미지 생성용 별도 계약으로 유지합니다. 비어 있으면 ClothSim 의상 생성만 실행합니다.

## 시연 순서

1. ‘예시 설명 넣기’를 누르거나 원하는 옷을 입력한 뒤 ‘AI 시안 만들기’를 누릅니다.
2. ‘디자인’ 탭에서 생성한 3D 옷을 드래그해 돌려봅니다.
3. 로고 PNG/JPG/WEBP를 첨부하고 ‘도안’ 탭으로 이동합니다. 펼친 재단 도안 위의 로고를 끌어 옮깁니다. 아래 슬라이더로 크기와 회전을 조절합니다. 마우스 휠은 로고 크기, Shift+휠은 회전입니다.
4. ‘디자인’ 탭에서 같은 장면에 로고가 반영됐는지 확인합니다. 탭을 바꿔도 생성 장면은 유지됩니다.
5. `completed === 1`이고 앞·뒷면 이미지가 모두 있을 때 ‘주문서와 도안 확인하기’가 활성화됩니다. 로고 수정 중에는 이전 캡처로 진행하지 못하도록 잠시 비활성화됩니다.
6. 주문 조건과 수령 정보를 입력하고 업체를 선택합니다. 최종 전달 화면 왼쪽에 앞·뒷면 이미지가 표시됩니다. 이미지 저장 링크도 제공합니다.
7. 앞·뒷면을 확인한 뒤 체크하고 ‘도안 전달하기’를 누릅니다. 전달 시점의 이미지는 주문의 독립된 보관본으로 저장되며 마이페이지 주문·제작자료 상세에서 다시 열 수 있습니다.

실제 업체 발송·결제는 시연 범위에 포함하지 않습니다. 캡처는 의류 제작 검토용 이미지이며, 인쇄 원본이나 업체 승인된 재단 파일을 대신하지 않습니다.

## 자료 유지와 복구

- 같은 탭 안에서 주문서를 다녀오면 메모리의 원래 장면을 다시 편집할 수 있습니다.
- 새로고침 후에는 저장된 앞·뒷면 이미지를 표시합니다. 3D와 재단 편집을 다시 열려면 같은 설명으로 재생성합니다.
- 새 디자인이나 보관함의 다른 디자인을 불러오면 이전 clothData를 지워 서로 다른 옷이 섞이지 않게 합니다.
- 저장 공간이 부족해 이미지를 보관하지 못하면 안내를 표시합니다. 새로고침 전에 이미지를 내려받으세요. 주문 저장 실패 시에는 완료 화면으로 넘어가지 않습니다.
- 도안과 주문 기록은 현재 탭의 sessionStorage에 보관됩니다. 탭을 닫기 전에 이미지를 내려받으세요. ‘저장’한 디자인의 미리보기는 기존 IndexedDB 보관함을 사용합니다.

## 정적 빌드 시연

`npm run build:pages`와 `npm run test:pages`로 검사합니다. 정적 미리보기에서도 Worker가 허용한 3000번 포트를 사용해야 실제 생성 요청이 허용됩니다.
개발 서버를 종료한 뒤 PowerShell에서 다음을 실행합니다.

```powershell
$env:PORT = '3000'
npm.cmd run preview:pages
```

주소: `http://127.0.0.1:3000/sb_hackathon/design/`.
기본 4173번 미리보기는 레이아웃 점검용이며, 현재 팀 Worker의 허용 Origin 목록에 포함되어 있지 않습니다.

브랜치를 운영 사이트에 반영하려면 검토 후 별도로 main에 병합해야 합니다. 저장소 Settings → Pages의 Source는 GitHub Actions를 사용해야 Next.js 빌드 결과가 게시됩니다.
