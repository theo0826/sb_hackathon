# 백엔드 팀원 인수 가이드

현재 범위는 **단색 반팔티에 로고 하나를 원하는 위치에 배치**하는 프로토타입입니다. 후드·과잠 선택, 줄무늬·원단 생성, 소매 배색, 독립 등번호는 제외했습니다. 앞가슴과 등판에 같은 로고를 재사용할 수 있습니다.

## 담당 경계

- 프론트: 티셔츠 3D, 이미지 첨부, 색상·로고 위치·크기 조절, 무료 테스트, 업체 자료 미리보기.
- 백엔드 팀원: 실제 DB 운영, API 키, 프롬프트 해석, 로고 생성/편집, 비공개 저장, 요청 제한과 장애 처리.
- 공통 계약: `lib/design.ts`, `docs/AI-API-CONTRACT.md`, `tests/fixtures/team-design.json`.

기존 Next.js의 `/api/`를 이어서 구현하면 됩니다. 별도 서버가 필요하면 같은 출처의 Next.js 프록시를 유지하고 브라우저에 비밀 키를 주지 않습니다.

## 고객 요청 흐름

1. 고객이 티셔츠 색상, 원하는 로고, 넣을 위치를 입력하거나 이미지를 첨부합니다.
2. 서버는 `garment=tee`, 단색 `color`, 로고 이미지, 앞/뒤 배치 1~2개를 반환합니다.
3. 업로드 원본은 그대로 재사용합니다. 새 로고를 요청했을 때만 생성하고, 명시적 재작업만 편집합니다.
4. 프론트가 같은 반팔 모델에 로고를 적용합니다. 업체 변환은 원본과 위치를 유지하며 목업 양식만 바꿉니다.

## 협업 방법

비공개 Git 저장소의 각자 브랜치에서 작업하고 PR로 합칩니다. `.env.local`, `.tools/`, `.next/`, 실제 사용자 자료는 공유하지 않고 `.env.example`만 공유합니다. 각 개발자가 자신의 서버 환경에 키를 설정합니다. 공통 타입 변경은 양쪽이 함께 검토하고 fixture·테스트도 갱신합니다. 원격 저장소 생성, push, 팀원 초대는 수행하지 않았습니다.

새 PC는 `npm ci` 후 `.env.example`을 `.env.local`로 복사하고 직접 설정합니다. 기존 환경 파일을 덮어쓰지 않습니다. `OPENAI_ENABLED=false`를 유지하고 `npm run dev`로 실행합니다.

- `npm run test:unit`: 네트워크·유료 AI 없이 계약/좌표/렌더러/가짜 AI 응답 검증.
- `npm run check:ai`: 로컬 설정만 확인, 키 값 출력 없음.
- `npm run check:sharing`: 공유할 파일·Git 인덱스·로컬 커밋 기록에서 비밀 값과 개인 경로를 검사합니다. 값은 출력하지 않으며 외부 요청도 없습니다. 상세 범위는 `docs/SAFE-SHARING.md`를 참고하세요.
- `npm run test:backend`: 로컬 서버 필요. Supabase에 QA 자료를 실제 저장하며 AI는 호출하지 않음.
- `npm run test:security`: AI OFF, 세션·외부 Host·비밀 파일 차단.
- `npm run build -- --webpack`: 현재 PC에서 확인한 프로덕션 빌드 명령.

## 현재 상태와 남은 일

유료 AI는 OFF입니다. 백엔드 팀원이 모델 권한·잔액·실제 해석/로고 품질과 운영 정책을 검증한 뒤 켭니다. 활성화는 `OPENAI_ENABLED=true`와 서버 재시작이지만 실제 서비스 완성을 뜻하지는 않습니다. 새 로고는 요청당 최대 1장, 배치 변경은 이미지 재생성 없이 처리합니다. 요청 수 제한은 금액 상한과 다릅니다.

서버는 `127.0.0.1:3000`에서만 열립니다. 저장 버튼을 누른 자료는 비공개 Supabase로 전송됩니다. 현재 게스트 쿠키 소유자 방식이라 쿠키 삭제/다른 기기에서 자동 복원되지 않습니다. 로그인·복구·보관 정책은 백엔드 후속 작업입니다.

업체 3곳과 봉제 패턴은 목업이며 실제 업체 발송·실측 재단 승인은 없습니다. 이전 저장 데이터는 삭제하지 않고, 편집 시 단색 반팔과 로고 배치로 정리합니다. 이전 모델 종류는 저장 호환용 타입/자산에 남아 있지만 현재 선택·생성 기능으로 제공하지 않습니다.
