요청서 확인은 PC의 820/400px 두 열과 모바일 한 열·하단 고정 전달 버튼으로 구성했다. 선택 업체·추천 상태·사이즈별 수량·수령일·견적을 실제 주문에서 읽는다. 앞·뒷면은 정적인 시안 의류 대신 현재 생성한 캡처 또는 저장된 주문의 캡처를 사용한다. 확인 체크를 해야 전달할 수 있으며, 도안이 바뀌면 확인 상태가 무효화된다. 주문 수정은 확인 대화상자를 거쳐 기존 주문서로 돌아간다.

전달 완료 화면은 중앙 760px 영역에 도안, 요청서, 보관 안내, 내려받기·마이페이지 버튼을 배치했다. 저장한 요청서와 주문의 전달 내역도 동일한 화면에서 원래 스냅샷으로 다시 확인한다. 기존 문서·주문 ID와 휴지통/복원 흐름을 유지했다. PDF 내려받기는 기존 PDF 생성기를 공유하고 견적 금액과 앞·뒷면을 포함한다. 앞·뒷면 이미지 원본은 각각 별도로 내려받는다.

마이페이지는 자료 보관 안내, 선택 상태가 표시되는 탭, 디자인 보관함, 주문·전달 내역과 제작자료 목록, 네 단계 이용 안내로 구성했다. 계정 버튼의 메뉴는 바깥 클릭·Escape·메뉴 이동으로 닫힌다. 새 디자인·이어서 만들기·디자인 삭제·요청서 삭제·실행 취소·휴지통 복원을 유지했다. 실제 주문이 없으면 빈 상태를 표시한다.

원본 정적 아이콘은 `public/figma/workspace`에 내려받았고 기존 동일 로고·헤더 자산은 재사용했다. 임시 Figma URL을 런타임에 참조하지 않는다. `WorkspaceAsset`에 SVG 원본 너비·높이를 기록했으며 PC/모바일에서 서로 다른 크기의 아이콘은 각각 원본 자산을 사용한다. 기존 로컬 Noto Sans KR/Inter를 공유한다. 휴대전화 시스템 상태 표시줄은 브라우저 UI에 추가하지 않았다.

추가 요청한 생성 대기 이미지 문제: 3D 복원 대기 분기에 빠졌던 전용 컨테이너를 복원하고 SVG에 기본 크기와 화면별 최대 크기를 지정했다. 대기 이미지 스타일은 디자인 스튜디오 내부로 한정했다. 생성 중 대기 이미지·화면 이동 후 제거와 생성 후 실제 3D 표시를 검사했다.

검증:

- Chrome 1440/1024/768/390/360px, 모든 표시 자산 로딩·원본 SVG 크기 일치·가로 넘침 없음·런타임 예외 없음.
- 요청서 확인 체크·전달·저장한 요청서 보기·마이페이지 탭/메뉴·주문/자료 연결·휴지통 삭제/복원.
- 실제 PDF Blob 생성과 `%PDF` 헤더, 앞·뒷면 원본 2장 다운로드 확인. PDF는 `.tools/request-account-downloaded.pdf`에 검증본을 보관했다.
- 실제 WebGPU 엔진으로 생성 중 PC/모바일 대기 이미지 크기, 저장·재로드·3D 복원·로고 편집·주문서 이동, 마이페이지에 대기 이미지가 남지 않음을 확인. 외부 AI 응답은 테스트 응답으로 대체했다.
- 기존 순차 견적·업체 정렬·선택·재요청·새 요청서 전달 흐름 회귀 검사 통과.
- 타입 검사·ESLint·기존 단위 테스트·프로덕션 Webpack 빌드 통과. 변경 화면 source taste lint 실패/경고 0.
- 화면 inspector 예외: 시안에서 요구한 앱 카드·그림자와 보조 색, 정적인 네 단계 안내 카드(`icon-cards`), 안내 화면에 불필요한 마케팅 모션(`still-page`), 사진/영상 기준. 시안의 구조·색·동작을 우선했다.

브라우저 화면 기록은 `.tools/request-account-*.png`, 대기 화면은 `.tools/resume-3d-loading-desktop.png`와 `.tools/resume-3d-loading-mobile.png`, inspector 기록은 `.taste-skill/inspect-request-account/`에 있다. 실제 업체 발송·결제와 기존 시연 범위는 변경하지 않았다.

## 사용자 후속 수정 · 주문별 제작자료 통합

별도의 ‘견적 요청서 · 제작자료’ 섹션을 제거하고 주문·요청서 전달 내역의 각 카드 안에 요청서 PDF와 앞·뒷면 도안을 함께 배치했다. 카드 제목에는 업체명과 단체명을 표시한다. 같은 업체의 주문이 여러 건이어도 주문 ID/요청서 ID로 연결하며, 아직 주문으로 전환되지 않은 보관 요청서도 업체·단체 정보와 자료를 하나의 카드로 표시한다. 제작자료를 삭제하면 주문은 유지하고 해당 주문 안에 휴지통 복원 링크를 표시한다.

타입·ESLint·새 연결 검사·프로덕션 빌드와 실제 Chrome 1440/1024/768/390/360px 화면 검증을 통과했다. 같은 업체 주문 2건과 다른 업체의 보관 요청서 1건에서 원래 요청서/캡처/다운로드가 각각 연결되고 중복 표시가 없음을 확인했다. 삭제·복원·새로고침과 기존 요청서 전달 흐름도 확인했다. 화면은 `.tools/order-history-desktop.png`, `.tools/order-history-mobile.png`에 보관한다. 이 수정은 위 원본 시안의 별도 자료 목록 구성보다 우선한다.
