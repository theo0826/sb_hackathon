# 2026-10-25 보안 및 저장 동작 검토

> 후속 수정: 전달 버튼에 마이페이지 기록 저장을 연결했습니다. 현재는 주문과 디자인 원본을 sessionStorage에 함께 기록한 뒤 완료 화면을 보여줍니다. 저장 실패는 완료로 처리하지 않으며 같은 전달 키는 중복 저장하지 않습니다. 실제 외부 발송·결제·생성된 의상 장면 저장은 연결하지 않았습니다. 아래 ‘마이페이지 주문 저장이 이루어지지 않음’은 이 수정 전 상태입니다.

## 변경과 확인

- npm 공식 레지스트리 감사에서 Next.js 16.4.0의 보안 권고 3개를 확인했습니다. Next.js와 eslint-config-next를 16.4.3으로 고정하고 lockfile을 함께 갱신했습니다. 설치 후 감사 결과는 등록 취약점 0건입니다. 참고: [이미지 최적화 API](https://github.com/advisories/GHSA-2464-fhr4-w9xw), [Server Actions 서비스 거부](https://github.com/advisories/GHSA-p3m5-59mp-jv5r), [use cache 반환값 처리](https://github.com/advisories/GHSA-673q-mjm6-r5xr). 실제 공격을 시도하지 않았으며 사이트의 악용 여부를 확정하는 검사는 아닙니다.
- Next.js 서버의 운영 CSP에서 JavaScript `unsafe-eval`을 제거했습니다. 개발 환경에서는 개발 도구를 위해 유지하며, 운영에서는 의상 엔진의 WebAssembly 실행에 필요한 `wasm-unsafe-eval`만 허용합니다. Next.js 초기화에 필요한 inline script 허용은 남아 있어 nonce 기반 엄격한 CSP는 아닙니다.
- 로컬 보안 테스트: 공개 Host와 변조된 forwarded Host는 403, 외부 Origin의 세션 생성은 403, 환경변수·Git 설정·서버 소스 파일 HTTP 접근은 404입니다. AI 비활성 상태와 응답 보안 헤더를 확인했습니다.
- 기존 개인 데이터베이스 연결은 비활성 상태에서 503으로 닫힙니다. 과거 보안 테스트의 401 기대는 백엔드 비활성화 이전 동작이어서 현재 503과 명시적 차단 오류를 확인하도록 갱신했습니다. 새 클라우드 연결이나 실제 고객 자료를 사용하지 않았습니다.
- 프론트엔드 전달 버튼은 실제 외부 발송 API를 호출하지 않습니다. 브라우저 네트워크 검사로 전달 클릭 후 POST가 없음을 확인했습니다. 화면과 완료 안내에 실제 발송·결제·마이페이지 주문 저장이 이루어지지 않음을 명시했습니다.
- 사용자 입력은 React 텍스트로 표시하며 이번에 HTML 삽입을 추가하지 않았습니다. 주문 정보 다운로드는 UTF-8 일반 텍스트 파일입니다. 스프레드시트 수식 또는 HTML 실행 형태로 내보내지 않습니다. 이미지와 생성된 의상은 이 파일에 포함되지 않음을 파일 안에 명시했습니다.
- 공유 검사에서 279개 작업 파일·Git 인덱스·28개 로컬 커밋과 628개 과거 blob을 검사해 비밀키 패턴 및 개인 경로 일치는 없었습니다. 로컬 환경변수 실제 비밀값과의 비교는 0개이므로 수행했다고 주장하지 않습니다. 커밋 이력에 GitHub noreply 이외의 작성자 이메일이 있어 공유 검사는 종료 코드 1을 반환했습니다. 기존 이력을 변경하지 않았습니다.

## 브라우저 저장의 실제 동작

| 자료 | 저장 위치 | 탭 종료 후 |
| --- | --- | --- |
| 작성 중 디자인·대화·주문 초안 | sessionStorage / 탭 메모리 | 새 탭에서 복원되지 않음 |
| 시연 주문·새 견적 요청서와 연결 도안 | sessionStorage | 새 탭에서 복원되지 않음 |
| ‘저장’을 누른 디자인·보관함에 별도 저장한 파일 | IndexedDB | 같은 기기·프로필·사이트 주소에서 유지 |
| 과거 목업 요청서 | 이전 localStorage 호환 읽기 | 같은 브라우저에 남을 수 있음 |
| 현재 전달 완료 표시 | React 화면 상태 | 새로고침 또는 화면 재진입 시 초기화 |
| 생성된 ClothSim 의상 장면 | 컴포넌트·WebGPU 메모리 | 새로고침 또는 화면 이탈 시 초기화. 디자인 저장 파일에 포함되지 않음 |

실제 Chrome에서 디자인을 저장하고 주문·요청서 테스트 자료를 넣은 후 탭을 닫아 새 탭을 열었습니다. 저장한 디자인은 유지되고 임시 디자인·주문·요청서는 비어 있는 것을 확인했습니다. 일반 새로고침에서는 임시 자료가 유지됩니다. 이 테스트는 별도 임시 브라우저 프로필에서 진행해 사용자의 보관함을 변경하지 않았습니다.

탭 닫기를 개인정보 영구 삭제 기능으로 취급하면 안 됩니다. 브라우저의 닫은 탭 복원·세션 복구 정책과 영구 저장 자료가 있으며, 서버 백업과 기기 간 동기화는 없습니다. 시크릿 모드 종료·사이트 데이터 삭제·저장 공간 정리 시 영구 보관함도 삭제될 수 있습니다. 같은 기기와 브라우저 프로필을 사용하는 사람은 저장한 자료를 볼 수 있습니다.

## 범위와 남은 제약

- 이 점검은 로컬 코드, 의존성 권고, 로컬 서버 접근 제어 및 브라우저 동작을 대상으로 했습니다. 침투 테스트나 외부 운영 백엔드·Supabase 프로젝트의 실시간 감사는 수행하지 않았습니다.
- GitHub Pages 정적 빌드는 서버 라우트·환경변수 파일·소스 디렉터리를 제외합니다. 정적 호스팅에는 next.config.ts의 HTTP 보안 헤더와 로컬 Host 검사가 적용되지 않으므로 운영 호스팅 측의 CSP·프레임 차단 헤더 설정은 별도 확인이 필요합니다.
- 로그인·사용자별 서버 저장·실제 도안 연결·업체 발송은 현재 제공되지 않습니다. 실서비스 연동 시 인증·권한·요청 제한·보관 및 삭제 정책을 서버에서 검증해야 합니다.
- 사용자 요청으로 코드와 빌드 결과만 수정했으며, 배포·커밋·푸시·유료 AI 호출은 하지 않았습니다.

검증 결과: 변경 코드 ESLint·타입 검사·단위 테스트·서버 운영 빌드·Pages 빌드 및 산출물 검사·개발/운영 서버 보안 테스트 통과. 운영 응답의 CSP에 JavaScript `unsafe-eval`이 없고 WebAssembly 전용 허용만 있는 것을 확인했습니다. 전체 `npm run lint`는 기존 루트 `.tmp-tree-detail.js`, `.tmp-tree-sum.js`, `.tmp-wasm-ctx.js`, `.tmp-wasm-prompt.js`, `.tmp-wasm-str.js`의 CommonJS import 오류 5개와 기존 경고 67개 때문에 실패했습니다. 사용자의 기존 임시 파일은 수정하거나 삭제하지 않았습니다.
