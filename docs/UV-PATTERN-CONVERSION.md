# 고객 UV → 업체 봉제·인쇄 패턴

고객 확인용 UV와 업체 봉제 패턴은 서로 다른 자료입니다. 변환의 목표는 고객이 확인한 도안 원본·위치·크기·방향을 업체 양식에서 재현하는 것입니다. 현재 실제 업체 자료가 없으므로 아래 세 양식을 목업으로 정의했습니다.

| 업체 | 목업 양식 | 기준 | 결과 |
| --- | --- | --- | --- |
| 장위 스튜디오 | `jangwi-cut-print / mock-v1` | 패널 좌상단, mm, 아래 방향 Y+ | 봉제·인쇄 SVG + PDF + JSON |
| 월곡 크래프트 | `wolgok-neck-placement / mock-v1` | 목 중심, cm, 아래 방향 Y+ | 배치표 SVG + 이메일 + 봉제 명세 JSON |
| 종암 메이커스 | `jongam-panel-package / mock-v1` | 패널 중심, mm, 위 방향 Y+ | 패널 SVG + 중심 좌표 JSON + 제작 PDF |

## 동작

1. 디자인과 주문 인쇄 치수에서 최종 고객 UV 스냅샷을 고정합니다. `originalDesign`, 도안 원본 경로, 앞/뒤 면, 정규화 중심 좌표, 실제 요청 인쇄 치수, 회전과 버전을 함께 저장합니다.
2. 선택 업체의 도안 템플릿을 불러옵니다. 템플릿에는 단위·원점·Y축 방향·패널 코드·시접/밑단 참고·필수 항목·출력 종류가 있습니다.
3. AI가 UV와 원본 도안, 템플릿, 검증 주문 정보와 기준 좌표를 보고 변환 명세를 구조화 출력합니다. 새 그림·새 봉제 형상을 생성하지 않고 지정 템플릿의 패널·좌표·작업 설명으로 변환합니다.
4. 서버가 명세를 고객 UV 기준으로 역변환합니다. 위치와 크기는 0.05mm, 회전은 0.01° 이내여야 합니다. 도안 버전·패널·단위·원점·시접이 바뀌거나 좌우 반전되면 거부합니다.
5. 봉제 패널·시접 참고 외곽·원단 결 방향·도안 배치를 SVG로 렌더링하고 업체별 JSON 및 PDF/이메일을 작성합니다. 동일 원본 이미지를 사용하며 재생성하지 않습니다.
6. 고객 UV, 업체 패턴, 좌표와 검증 결과를 한 화면에서 검토합니다. 주문과 두 자료의 원본을 같은 Supabase 견적 기록에 저장합니다.

`/patterns`에서 목업 3종을 직접 바꿔 보면서 확인할 수 있습니다. 의류(반팔·후드·과잠), 앞뒤 면, 회전을 바꾸어 좌표 변환을 비교하고 SVG·JSON·PDF 또는 이메일을 내려받습니다. 같은 예시로 주문 화면에 이동해 서버 저장 흐름도 확인할 수 있습니다.

## 고객 UV의 치수

UV 스냅샷은 주문 화면에서 확정하는 인쇄 가로·세로(cm)를 반영한 최종 배치입니다. 원래 디자인의 위치와 회전을 유지하면서 이 인쇄 치수로 최종 UV와 의류 확인 화면을 구성합니다. 업체 변환은 이 스냅샷을 기준으로 하므로 주문 인쇄 치수를 나중에 바꾸면 새 UV 확인과 변환이 필요합니다. 기존 디자인 화면의 추상 배율이 곧 공장 인쇄 치수라고 가정하지 않습니다.

## 봉제 패턴 목업

반팔은 앞판·뒷판·좌우 소매·목 리브, 후드는 앞판·뒷판·소매·후드·주머니, 과잠은 몸판·소매·리브의 참고 패널을 제공합니다. 치수는 가상 M 한 사이즈이며, SVG에는 봉제 기준선·시접 참고 외곽·원단 결·인쇄 배치를 분리합니다. 시접 참고선은 목업용 외곽 확장이므로 실제 곡선 시접으로 확정하지 않습니다.

다른 사이즈 주문 수량도 정확하게 기록하지만 패턴 그레이딩을 임의로 만들지 않습니다. 소재 수축률·실측·사이즈별 패턴·과잠 여밈 분할은 실제 업체 자료가 오면 반영합니다. 따라서 항상 `graded=false`, `approvedForCutting=false`입니다. 봉제 영역과 여밈을 침범하는 배치는 `needs_review`로 표시합니다.

## 비용 없는 목업 확인

`POST /api/quotes`에 `conversionMode: "sample"`을 명시하면 같은 좌표·렌더링·저장 파이프라인을 사용하되 AI 응답을 예시 변환 명세로 대체합니다. UI와 결과에 목업 변환임을 표시하며 유료 AI 호출과 AI 작업 한도를 소비하지 않습니다. 기본 또는 `conversionMode: "ai"`는 실제 AI 변환 코드이며 `OPENAI_ENABLED=true`일 때만 호출할 수 있습니다. 현재 비용 보호 요청에 따라 활성화하지 않았습니다.

목업 요청은 `requestKey` UUID로 중복 저장을 방지합니다. 동일 세션·키·입력은 기존 결과를 반환하고 입력이 달라지면 409입니다. AI 요청은 기존 DB 작업 예약과 재시도 복구를 사용합니다. 다른 세션은 저장한 UV·패턴·원본 도안을 조회할 수 없습니다.

## 파일과 코드

- `lib/production-mapping.ts`: 목업 3종, UV 스냅샷, 단위·원점 변환과 역검증, 봉제 패널.
- `lib/production-document.ts`: 목업/AI 명세를 공통 제출 자료로 조립.
- `lib/production-svg.ts`: 고객 UV·업체 패턴 SVG와 업체별 JSON.
- `lib/server/ai.ts`: 실제 AI의 구조화 변환. 불필요했던 이메일 전문 AI 출력은 제거.
- `components/supplier/PatternComparison.tsx`: 두 자료의 비교·검증·다운로드.
- `components/supplier/PatternDemo.tsx`: 세 양식 체험 화면.
- `lib/production-export.ts`: 기존 PDF에 고객 UV와 업체 봉제 패턴 페이지 추가.

## 검증

```powershell
node tests/production-mapping.mjs
node tests/ai-contract.mjs
# 로컬 서버 + Supabase 키, 유료 AI 비활성화 상태에서
node tests/backend-api.mjs
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
```

변환 시험은 의류 3종 × 앞뒤 2면 × 회전 3종 × 업체 3종의 54개 조합을 확인합니다. AI 시험은 가짜 응답만 사용하고 실제 API를 호출하지 않습니다. 실물 의류 결과 일치는 아직 실제 업체 패턴과 시제품으로 검증되지 않았으며, 현재 검증 범위는 목업 좌표·동일 도안·문서 출력입니다.

완료한 화면 검증: 1440px/390px에서 목업 3종의 UV·패턴 표시, 확대/스크롤, 앞뒤·회전·후드 변경, SVG·JSON·PDF/이메일 다운로드, 주문 화면에서 목업 변환·저장, 상세 화면 이동과 새로고침 복원. PDF 2종은 고객 UV와 업체 봉제 패턴을 포함한 3페이지로 렌더링해 확인했습니다. 소스 디자인 검사, 타입 검사, ESLint 및 프로덕션 빌드도 통과했습니다. 이 작업에서는 유료 AI를 호출하지 않았습니다.
