# 노션 QA 디자인 재검수 — 2026-11-02

기준: [한땀 QA 목록 / 11.2 오전 1:05](https://app.notion.com/p/40758f80c56680a2bc07e7de0e163735). 원문을 다시 조회해 비교했다. 모바일 4번·PC 3번은 사용자 지시대로 보류했다. 수정 대상은 모바일 8개, PC 15개이며 중복 요구도 각각 확인했다.

## 이번에 발견하고 보완한 부분

1. **이전 이미지의 마네킹 손상과 배경 띠.** 매 행의 왼쪽 픽셀을 배경으로 간주하던 코드가 가장자리에 닿은 팔 일부를 지웠다. 렌더러의 기존 단색·smoothstep 배경으로 판단하며, JPEG 색 오차는 양쪽 가장자리가 알려진 배경과 일치할 때만 보정한다. 배경과 이어진 영역만 변경하며 원본 다운로드는 보존한다. 실제 이전 JPEG의 팔 아래 두 지점이 `247,248,250,255`, 팔 픽셀이 기존 `138,137,132,255` 그대로임을 브라우저에서 확인했다.
2. **주문 요약 이미지의 회색 경계.** 정규화된 이미지에 남아 있던 `mix-blend-mode:multiply`가 배경과 옷 색을 다시 어둡게 만들었다. 정상 합성으로 변경했다.
3. **PC 미니 도안 앞·뒤 라벨 잘림.** 패널만 중앙에 맞추면서 글자 공간을 빠뜨렸다. 라벨 공간 20px를 확보하고 실제 캔버스 글자 좌표의 하단 여백과 드래그 후 재캡처를 검사했다.
4. **주문 단계 화살표 간격.** 글자와 목록 gap은 맞았지만 단계 안에 들어간 화살표 여백이 달랐다. 화살표 폭 12px, 양옆 실제 간격 9px로 정리했다.
5. **좁고 긴 모바일 3D의 소매 잘림.** 데스크톱용 추가 확대와 세로 고정 시야각 때문에 320px에서 소매가 잘리고 안내와 겹쳤다. 모바일 추가 확대를 없애고 종횡비가 0.65보다 작을 때 투영 범위를 보정했다. 사용자 확대·회전 값과 정사각형 캡처 구도는 유지한다. 320/360/390/430px에서 기본 생성 의류의 실제 픽셀에 좌우 12px 이상 여백이 있는지 검사했다.

## 검사 범위와 근거

- 실제 Chrome/WebGPU의 로컬 앱. 생성 화면은 320/360/390/430/700/701/768/820/1024/1280/1440px의 11개 폭, 주문서·팝업·요청서는 해당하는 다수 폭에서 검사했다. 모든 페이지×모든 폭의 전수 조합 검사를 의미하지 않는다.
- `.tools/verify-notion-qa-expanded-ui.mjs`: 주문서·팝업·요청서·완료·상세·이용 방법·종류 표시, CSS/픽셀 검사, 가로 넘침·런타임 오류 검사 통과.
- `.tools/verify-notion-qa-expanded-live.mjs`: 실제 생성·로고·미니 드래그·저장·복원·주문 복귀, 캔버스 라벨 및 모바일 의류 픽셀 여백 검사 통과.
- `.tools/notion-qa-*.png`: 직접 열어 확인한 화면. 고정 하단 버튼이 전체 페이지 캡처의 중간에 보이는 현상은 실제 뷰포트와 구분했다. 일부 즉시 이동 캡처에는 기존 진입 애니메이션의 중간 투명도가 포함된다.
- `tests/capture-background.mjs`: 가장자리에 닿은 팔, 내부 로고, 단색·그라데이션 배경, 관계없는 색상 보존 회귀 검사. `npm run test:unit`에 포함했다.
- TypeScript, 단위 테스트, 변경 코드 ESLint, `build:pages`, `test:pages`, `git diff --check` 통과. ESLint 오류 0, 기존 PatternEditor hook/미사용 변수 경고 7개는 남는다.
- 디자인 스킬 소스 검사 0 FAIL/0 WARN. 화면 inspector는 `.taste-skill/notion-qa-strict/report.json`, 1440/768/390px에서 0 FAIL/0 WARN. 기존 Figma 제품 UI의 구분선·작은 보조 글자·비활성 대비 및 마케팅 사진/모션 규칙 예외를 유지했다.
