## 기능 보존 범위

`ClothSimulationPreview`는 모달을 열어도 동일한 컴포넌트·장면을 유지합니다. 3D 생성, 서버 요청, 물리 계산, 로고 좌표 변환, 캡처, 완료 검증은 기존 연결을 사용합니다. 도안 편집기의 변경은 색·표시 스타일과 읽기 전용 썸네일 옵션이며, 기존 드래그·휠 처리 함수는 보존했습니다.

로고를 변경하면 기존 완료 캡처를 무효화하고 새 앞·뒷면이 준비될 때까지 다음 진행을 막습니다. 새로고침 후 저장한 캡처만 있는 경우 기존 안내와 재생성 조건을 유지합니다. 저장 및 주문서 이동은 기존 함수를 사용합니다.

후속 주문서·업체·주문 화면은 CSS 색상 토큰과 버튼 모양만 맞췄습니다. 해당 화면의 컴포넌트·계산·검증·전달 코드는 수정하지 않았습니다. 홈의 기존 디자인과 `.taste-skill/direction.json`은 유지했으며 새 방향을 추첨하지 않았습니다.

## 확인

- TypeScript 및 변경한 TSX 파일 ESLint 통과.
- 기존 재단 편집기 JS의 ESLint 지적은 원본과 비교해 오류 6개·경고 7개로 동일함을 확인했습니다. 이번 디자인 작업에서 기존 ref/효과 처리 코드를 재작성하지 않았습니다.
- 실제 Chrome의 1440×900, 768×1024, 390×844 화면을 확인했습니다. 모바일 제목 줄바꿈, 좁은 태블릿의 예시 배열, 모달·입력창·가격 영역을 보며 수정했습니다.
- 별도 브라우저에서 실제 WebGPU 엔진과 모델 응답 대역으로 생성·캡처·동일 장면 유지·로고 업로드·드래그·너비 변경·캡처 재생성·모바일 가격 상세·저장·주문서 이동을 확인했습니다. 가로 넘침과 미처리 런타임 예외는 없었습니다.
- 추가로 기존 팀 Worker에 실제 생성 1회를 요청했습니다. 11개 요청 후 반팔 3D 및 앞·뒷면 캡처가 완료됐고 다음 버튼이 활성화됐습니다. 개인 AI 키나 별도 서버를 연결하지 않았습니다.
- 세부 전체 기능 회귀검사는 후속 Astra 작업 범위로 남깁니다. 이 작업은 디자인 구현 및 위 주요 연결 확인에 한정합니다.

로컬 화면 기록은 `.tools/figma-initial-*.png`, `figma-generating-desktop.png`, `figma-generated-*.png`, `figma-editor-no-logo-*.png`, `figma-editor-logo-*.png`, `figma-mobile-price-sheet.png`, `figma-order-mobile.png`에 있습니다. 실제 서버 확인 기록은 `.tools/figma-live-debug.json`입니다. 대역을 사용한 검사는 `.tools/verify-figma-studio.mjs`, 실제 요청 검사는 `.tools/verify-figma-live.mjs`입니다.

## 디자인 검토

Figma V1의 연한 회색 작업 영역, 남색 동작 버튼, 연두 포커스·로딩을 기준으로 조절했습니다. 예시 문장과 생성 결과가 화면의 중심이고 오른쪽 정보는 고정된 자리에서 상태만 바뀝니다. 모바일은 로고 편집을 전체 화면, 견적 상세를 바텀 시트로 분리했습니다.

`design-taste-frontend`의 실제 브라우저 inspector와 소스 lint를 실행했습니다. 마케팅 페이지용 사진·영상 개수, 모션 개수, 예시 카드 감지와 비활성 버튼 대비 지적은 이 편집기 및 사용자가 제공한 시안에 맞춰 적용하지 않았습니다. 얇은 입력 테두리·떠 있는 프롬프트/모달의 그림자도 시안에 포함된 앱 UI 규칙으로 유지합니다. 전체 페이지에 붙였던 `data-ui`는 제거하고 실제 입력 위젯에만 적용했습니다. 일반 랜딩 페이지 기준 통과로 보고하지 않습니다.
