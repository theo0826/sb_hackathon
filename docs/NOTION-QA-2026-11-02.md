## 검증

- `npm run typecheck`, `npm run test:unit`, `npm run build:pages`, `npm run test:pages`.
- 변경 TSX와 ClothSim JS의 ESLint: 오류 0. 기존 엔진의 hook 의존성 등 경고는 남아 있다.
- 실제 Chrome/WebGPU. 모델 응답만 대체했으며 실서비스 모델 호출은 하지 않았다. 생성→로고 등록→PC 미니 도안 드래그→실제 3D 재캡처→저장→복원→수정→주문서 복귀·새로고침을 검사했다. 3D binary 원본 동일성과 저장본 간 독립성도 확인했다.
- 모바일 390px: 편집 제목 중앙 오차 1px 미만, 로고 없는 회색 슬라이더, 회전 안내 2회 애니메이션·45% 고정·실제 두 손가락 확대 후 숨김을 검사했다.
- 주문서 날짜는 320/360/390px에서 44px와 카드 안의 폭을 확인했다. PC 제목·안내·단계 글씨, 남색 라디오/중앙 점/선택 카드, 팝업·요청서·전달 완료·주문 상세·이용 방법을 확인했다. 가로 넘침과 미처리 런타임 예외는 없었다.
- 검증 스크립트: `.tools/verify-notion-qa-live.mjs`, `.tools/verify-notion-qa-ui.mjs`. 화면: `.tools/notion-qa-*.png`, 측정: `.tools/notion-qa-ui-metrics.json`.
- 기본 Turbopack 빌드는 이 Windows 환경에서 PostCSS 자식 프로세스 연결 오류로 실패했다. 프로젝트가 기존에 사용하는 `build:pages`의 Webpack 정적 빌드는 통과했다. 게시·커밋은 하지 않았다.

## 디자인 검사

대상은 기존 Figma 제품 UI의 QA 수정이다. 소개 페이지의 사진 수·영상·다수 입장 모션 기준을 적용해 새 콘텐츠를 만들지 않았다. 기존 폼·헤더의 구분선, 카드 외곽선, 비활성 버튼·보조 문구 대비도 유지했다. 이 항목들은 수정 전 inspector에서도 관찰한 기존 디자인 예외이며, `hairline,outlined-box,contrast,few-pictures,still-page,no-footage,small-text`로 명시했다. 최종 검사 결과는 `.taste-skill/notion-qa-final/report.json`에 있다. 소스 taste 검사 오류는 0이며 기존 출력값의 em dash 경고만 남아 있다.

화면 검토에서 날짜의 네이티브 안내와 커스텀 안내가 겹치는 문제를 찾아 수정하고 다시 확인했다. PC 생성 실루엣은 중앙에 있고 상태 문구가 보이며, 미니 앞뒤 패널·주문서 이동 버튼은 실제 결과 상태에 연결된다. 모바일 편집 제목·날짜·회전 안내도 시각 검토했다. 앱 QA 기준 자체 평가: 디자인 8, 사용성 8, 일관성 8. 기존 화면의 작은 보조 글씨와 네이티브 달력의 플랫폼별 표현은 유지된다.
