# 비공개 저장소 공유

`.env.local`에 실제 키를 보관하고 `.env.example`에는 빈 키와 예시 설정만 둡니다. 팀원은 직접 자신의 환경 파일을 설정합니다. 실제 키를 GitHub 파일·이슈·PR·채팅에 붙여 넣지 않습니다.

## Git 제외 대상

- 환경 파일, 인증서·개인 키, 계정 인증 파일
- 로컬 편집기·에이전트 상태, 배포 계정 연결 정보
- `private/`, `uploads/`, `public/uploads/`, `storage/`, `backups/`, `dumps/`의 실제 사용자 자료와 백업
- 로컬 DB, 브라우저 로그인 상태, 테스트 녹화·로그·보고서
- 의존성, 빌드 결과, 기존 `.tools/`·`.taste-skill/` 임시 자료

백엔드 소스, `supabase/schema.sql`, 키가 빈 `.env.example`, 라이선스와 합성 테스트 fixture는 공유합니다. 개인정보 파일은 임의의 소스 폴더에 넣지 말고 `private/`에 두세요. `.gitignore`는 Git 제외 규칙이며, 웹 접근 차단이나 암호화 기능은 아닙니다. 특히 `public/`에는 실제 사용자 자료나 비밀 파일을 두지 않습니다.

## 올리기 전 확인

`npm run check:sharing`은 현재 공유 대상 파일, 스테이징된 내용, 로컬의 모든 Git 참조에 연결된 커밋을 읽습니다. 현재 환경 파일의 실제 비밀 값과 비교하고 주요 토큰 형식·개인 경로·로컬 계정 이름·커밋 이메일도 확인합니다. 결과에는 값 대신 파일과 검사 종류만 표시됩니다. 네트워크·AI·DB 요청은 없습니다.

검사 후 `git diff --cached --stat`으로 올릴 파일을 확인합니다. 실제 데이터의 사진·PDF·영상·임의 형식의 개인정보는 자동 검사로 모두 식별할 수 없어 별도 확인이 필요합니다. 이미 원격에 있던 내용과 로컬에 없는 원격 기록까지 검사하는 명령은 아닙니다.

`.gitignore`는 이미 추적되거나 커밋된 파일을 삭제하지 않습니다. 과거에 비밀 키를 올린 사실이 확인되면 해당 서비스에서 키를 폐기·재발급한 뒤 Git 기록 정리를 별도로 진행해야 합니다. 비공개 저장소에도 동일하게 적용합니다.

저장소는 Private으로 유지하고 필요한 팀원에게만 접근 권한을 줍니다. 코드 공유가 유료 AI 활성화나 사이트 배포를 뜻하지 않습니다. 기본 `OPENAI_ENABLED=false`를 유지합니다.

## 2026-10-16 업로드 전 점검

- 공유 대상 151개 파일·인덱스·가져온 원격 참조를 포함한 4개 커밋을 확인했습니다. 로컬 환경 파일의 실제 비밀 값, 주요 토큰 형식, 개인 홈 경로·계정 이름·PC 이름과 일치하는 내용은 발견되지 않았습니다. 비밀 값은 검사 결과에 출력하지 않았습니다.
- Google·Slack·Stripe·npm·SendGrid 토큰, 사설 IP·MAC 주소·인증정보를 포함한 HTTP 주소도 추가 확인했으며 일치 항목은 없었습니다. 기존 이미지·모델 자산 외 신규 업로드 미디어는 없습니다.
- 환경 파일·로컬 캡처·브라우저 인증·편집기 상태의 Git 제외를 확인하고, 개인 Git 인증 파일·SSH 개인 키·클라우드 인증 설정·OS 메타데이터 제외 규칙을 보강했습니다. 예시 환경 파일의 키는 비어 있습니다.
- 이미 원격에 있는 다른 기여자의 커밋 메타데이터에서 일반 이메일이 확인됐습니다. 전체 참조 검사에서는 해당 항목을 계속 경고합니다. 기록을 강제로 수정하지 않았으며 이번 커밋은 GitHub noreply 이메일을 사용합니다.
- 원격 `main`에 추가된 별도 작업을 보존하기 위해 이번 변경은 `codex/resident-glass-workflow` 브랜치로 공유합니다.

자동 패턴 검사와 수동 검토의 결과이며 모든 형태의 민감정보 부재를 보증하는 것은 아닙니다.
