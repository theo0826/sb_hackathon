## 빨간 주석 대응

- PC: 오른쪽 요약·견적은 유지하고 왼쪽 입력 영역만 스크롤한다. 낮은 화면에서는 의류 미리보기 높이를 줄인다. 상단 완료 배너와 별도 확인 체크박스는 제거했다.
- 명단: 사이즈별 수량과 개인별 명단을 전환하며 각 탭의 입력을 따로 보존한다. 개인별 명단은 1인 1벌이고 사이즈 수량을 자동 합산한다. 처음 4명, 전체 보기·접기, 행 추가·삭제, 이름칸 포커스, 이름·사이즈·필수 인쇄 문구 오류를 제공한다.
- CSV: 빈 상태에서 파일을 끌어 놓거나 선택할 수 있다. 양식 다운로드와 직접 추가를 제공한다. 기존 명단 교체는 ‘취소/바꾸기’를 확인하며 취소하면 기존 값을 보존한다. 기존 UTF-8/BOM·인용문 파서, 1MB·500명 제한을 사용한다.
- 납기·수령: 방문 수령은 배송 주소 대신 협의 안내를 표시한다. 배송으로 돌아오면 입력했던 주소를 복원한다. 주소는 직접 입력한다.
- 요약·견적: 생성된 앞·뒷면 캡처, 의류, 수량, 사이즈, 제작 방식, 수령 방법, 수령일을 실시간 반영한다. 단가와 총액은 디자인 화면과 동일한 계산을 사용한다. 디자인 수정으로 돌아가도 주문 입력을 유지한다.
- 다음 단계: 수량·명단, 유효한 수령일, 택배 주소, 단체 이름, 이메일을 검사하고 첫 오류로 이동한다. 접힌 명단의 오류도 펼쳐서 보여준다. 실제 앞·뒷면 캡처가 준비되어야 진입·이동할 수 있다. 유효한 폼의 견적 요청을 확인으로 기록한 후 기존 업체 선택 화면에 연결한다.
- 모바일: 명단 → 납기·수령 → 담당자·결제 → 접이식 주문 내용 → 예상 금액 순서다. 하단 견적 버튼은 고정하고 가상 키보드가 열리면 숨긴다. 수령·결제 라디오 한 줄 전체를 누를 수 있다. 입력 높이 44px, 입력 글자 16px, 하단 명단 편집 시트와 삭제 확인을 제공한다.

## 검증

- TypeScript, 변경한 TSX/공용 주문 모델 ESLint, 기존 전체 단위 검사 통과.
- 실제 Chrome 1440·1024·768·390·360px 화면 확인. 768px 높이 PC도 확인. 가로 넘침과 미처리 런타임 예외 없음.
- 별도 스크립트 `.tools/verify-order-review-v1.mjs`: 진입 캡처 검증, PC 독립 스크롤·견적 버튼 노출, 탭별 수량 보존, CSV 교체/취소, 직접 수정·행 추가 포커스, 명단 펼치기, 모바일 저장/삭제 확인, 필수 입력 이동, 주소 복원, 새로고침 보존, 주문 요약, 키보드 시 CTA 숨김, 기존 업체 선택 진입 검증.
- 브라우저 검증에는 기존 의류 캡처 fixture를 사용했으며 생성 API나 업체 발송을 호출하지 않았다.
- taste 소스 검사: 실패·경고 0. 실제 페이지 측정은 `.tools/order-review-inspection.json`에 기록한다. 실제 폼·표에 필요한 테두리와 구분선은 시안대로 유지한다. 이 작업은 제품 입력 화면이므로 마케팅용 사진 수·영상·UI 영역 크기 기준은 적용하지 않는다. 미래 단계와 ‘선택 전’의 약한 보조 글자 대비는 시안 상태 구분으로 유지한다.
